# Probe Kit Guide — how the modular probes work, and every piece there is

**What this is.** The working guide to the probe kit under `Tools/visual-regression/`: what each part owns, how a
probe runs on it, how to build a new probe from its pieces, and (§4) a generated inventory of every kit piece, rig,
metric and runtime probe. Written from the code at `49c2cbbcee` (Batch 1578) on 2026-10-09, where every file, export
and line cited below was re-read; the inventory (§4) and the counts quoted in §1 and §5 were regenerated at
`7eeae0fbaa` (Batch 1582), and none of the files cited by line changed between the two. Line numbers move; re-read
before relying on one (CLAUDE.md Principle 10).

**Authority.** The maintainer's directive of 2026-10-08, quoted: "We want to take all of our probes and turn them into
modular pieces that we can use to quickly build and reuse probes in the future so that we spend the absolute minimum
time working on probes going forward. From now on when we need probe functionality, we first see if it already exists
then if it doesn't we create a new modular piece. Lets get all of our probe tech shored up and ready to rock." The
rule is restated in `CLAUDE.md` ("Probe Kit - Kit First") and pointed at from `AGENTS.md`. The kit's rows are
`DX-01`, `DX-02`, `DX-06` and `DX-101` … `DX-108` in
[QUEUE_2026-08-29_RESEARCH_DISPATCH.md](QUEUE_2026-08-29_RESEARCH_DISPATCH.md) §6a.1; the plan they came from is
[PROBE_KIT_PLAN_2026-09-17.md](PROBE_KIT_PLAN_2026-09-17.md).

**Keeping it true.** §4 is generated by
[probe-kit-inventory.mjs](../Tools/visual-regression/probe-kit-inventory.mjs). A change that adds or removes a kit
piece, a metric, a rig or a runtime probe regenerates it in the same change:

## 1. What the kit is

A probe on the kit is four small things and nothing else: a **rig** (the scene, as data), a **stage or step piece**
(the page-side code that puts the rig's dials on the page), one or more **metrics** (pure Node functions over decoded
pixels), and a **descriptor** handed to the shared **runtime**, which owns everything a probe used to copy: argument
parsing, the served-build check, the Edge slot, the browser, the capture, the receipt and the exit code. Two further
tools sit beside them for looking at results: the **capture seam** and the **contact sheet**.

| part | home | what it owns | row |
| --- | --- | --- | --- |
| runtime | [lib/probe-runtime.mjs](../Tools/visual-regression/lib/probe-runtime.mjs) | `runProbe`, argv, preflight, Edge slot, Edge launch, element capture, receipts, exit codes | `DX-01`, `DX-06` |
| lifecycle | `lib/probe-lifecycle.mjs`, `lib/probe-lifecycle-run.mjs`, `lib/probe-work-registry.mjs` | the opt-in derived deadline and bounded shutdown | `C13-42a` |
| refusals and slot | `lib/probe-refusal.mjs`, `lib/probe-edge-slot.mjs` | the exit-code table, `ProbeRefusal`, the one-Edge-job lock | `DX-01` |

| rigs | [lib/rig-registry.mjs](../Tools/visual-regression/lib/rig-registry.mjs) + `rigs/*.mjs` | scenes as frozen data; `RIG_TAGS`; `scenes.json` regenerated from the wave-end rigs | `DX-101` |

### 1.1 The runtime (`lib/probe-runtime.mjs`)

A probe hands `runProbe(descriptor)` (`probe-runtime.mjs:1004`) a descriptor and gets back an exit code. The order is
fixed: parse the arguments, preflight the served build, take the Edge slot, and only then open a browser, so every
refusal that needs no GPU is decided before one is claimed.

- **Descriptor fields** (JSDoc at `:975-1003`): `name`, `title`, `outputSubdirectory`, `args` (`defaults`,
  `extraOptions`), `servedArtifacts`, `launchArgs`, `receiptEnvelope` (`probe-owned` or `runtime`), `workBudgetMs`,
  `cells` (returns an ARRAY of cells), `receipt`, `verdicts`, `summary`. A probe guards its call with
  `isEntryPoint(import.meta.url)` (`:967`) so a spec can import its pure functions without launching anything.
- **Core flags** (`CORE_OPTION_SPECS`, `:191`): `--port` (default 8094), `--runs`, `--reverse`, `--headed`,
  `--renderer` (`webgl`, `webgpu`, `both` or a list), `--serve-built` / `--no-serve-built` (the assertion is ON by
  default), `--repository-root`, `--output`, `--timeout-ms`. A probe adds its own through `args.extraOptions`.
  Port 8080 is refused while the arguments are parsed (`port-8080-forbidden`, `:349-355`): the default dev server
  on 8080 serves a live build of the source tree, so a probe there cannot tell which build it measured.
  **Today that refusal crashes instead (open defect `DX-96`, [DEFERRED_WORK.md](DEFERRED_WORK.md) "DX-96").** A
  refusal or error raised while the arguments are parsed (port 8080, or an unknown flag, `:313`) leaves `options`
  unassigned; `buildRuntimeReceipt` then reads `options.servedBuild` off `null` (`:833`, called from `:1224`), and
  `runProbe` rejects with a `TypeError` instead of returning 3 (or 2). No browser is opened and nothing is written,
  no refusal or error record either, and the process exits **1**, the FAILURE code (§2.3).
- **Served-build preflight.** `--serve-built` asserts that the bytes the origin serves are the bytes on disk under
  `--repository-root`. The default set is `Build/CesiumUnminified/Cesium.js` and
  `packages/engine/Build/Unminified/index.js` (`lib/served-build-preflight.mjs:36-39`); a descriptor widens it with
  `servedArtifacts`. A mismatch refuses `served-build-preflight-failed` or `served-build-preflight-incomplete`
  (`decideServedBuildRefusal`, `:373`). The flag does not start a server; the server is started separately with
  `node server.js --serve-built --port <port>`.
- **Edge slot.** One Edge job at a time, held by an exclusive-create lock at
  `Tools/visual-regression/output/.edge-slot.lock` (`lib/probe-edge-slot.mjs:33-34`), stale after two hours
  (`:41`); a held slot refuses `edge-slot-busy`.
- **Browser.** Edge (`msedge`), one browser per run, launched with `--enable-unsafe-webgpu` and nothing else
  (`EDGE_LAUNCH_ARGS`, `:496`). A probe that needs other flags declares `descriptor.launchArgs`, and the receipt
  records them.
- **Element capture.** `captureElement` (`:687`) screenshots ONE element, never the page. The selector must match
  exactly once or name an `index` (`capture-selector-ambiguous`). Before the bytes reach the disk it asks the page's
  WebGPU error gate whether the device is alive (`capture-device-lost`; a lost device still answers a screenshot
  with its last frame) and, for a declared control, whether the frame was redrawn (`capture-frame-not-redrawn`).
  The capture record is `{name, path, byteLength, sha256, matchCount, liveness: {state, frameNumber}}`.
- **The WebGPU error gate.** The runtime READS the gate at every capture; it does not install it. The probe (or its
  stage piece, as `lib/voxel-probe-page.mjs` does) installs `errorGateInit` with `page.addInitScript` before the
  page loads and calls `armWebGPUDevices` once the viewer exists. A page with no armed gate captures as liveness
  `unobserved`, which the record says.
- **Frame driver.** `driveSceneFrames` / `installSceneFrameDriver` (`lib/probe-scene-frames.mjs:61`, `:120`,
  re-exported by the runtime) render a scene one frame at a time by requesting the next render from every
  `postRender`, so a step sequence works on `Apps/CesiumViewer`, which runs in request-render mode. A run ends
  `done`, `frame-cap`, `deadline` or `step-error`; the wall-clock deadline resolves it even when no frame arrives.
- **Origins and readiness.** `installSandcastle2OriginRewrite` (`:528`) serves probes that open the built
  Sandcastle2 app; `decideOriginRefusal` (`:411`) refuses a navigation that left the requested origin
  (`origin-mismatch`), and `decideRenderReadyRefusal` (`:454`) refuses a settle gated on `scene.renderReady` that
  never saw it (`render-ready-absent`, `render-ready-timeout`).
- **Receipts.** A run that MEASURED writes `<name>-report.json` and `<name>-summary.md` into
  `Tools/visual-regression/output/<outputSubdirectory or name>/` (or `--output`). With the default `probe-owned`
  envelope the report is the probe's own fields and the runtime's record goes beside it as `<name>-runtime.json`;
  with `receiptEnvelope: "runtime"` there is one report carrying both (`:1249-1288`). The runtime record is `probe`,
  `generatedAt`, `origin`, `options`, `servedBuildAssertion`, `preflight`, `edgeSlot`, `launchArgs`, `captures`,
  `verdicts`, `exitCode` (`buildRuntimeReceipt`, `:816`). A run that REFUSED or ERRORED writes no receipt at all and
  leaves the banked one untouched; it writes `<name>-refusal.json` or `<name>-error.json` instead (`:1289-1309`),
  except for a refusal or error raised during argument parsing, which writes neither (`DX-96`, above).
- **Exit codes** (`lib/probe-refusal.mjs:28-33`): 0 OK, 1 FAILURE (a measured red), 2 ERROR (the harness broke),
  3 REFUSAL. A refusal outranks a measured red. Until `DX-96` is fixed, a parse-time refusal or a bad flag exits 1
  with a stack trace instead of 3 or 2.
- **The lifecycle is opt-in, by one field.** A descriptor that declares `workBudgetMs` (a function returning the
  milliseconds its work needs per run) runs inside `withProbeLifecycle` with a derived deadline of
  `60,000 + runs × (120,000 + work + 60,001)` ms (`lib/probe-lifecycle-run.mjs:38-63`, `:73`), a hard stop
  16,001 ms after draining begins, and `scope` handed to its `cells`. A descriptor without it takes the original
  path: one browser per run in a `try/finally`, no deadline (`:1033`).
- **Residency.** A probe on the runtime carries `// @runtime lib/probe-runtime.mjs` in its header beside `@purpose`
  and `@status`, and `lib/runtime-residency-contract.mjs` refuses a hand-rolled hash, lock, refusal writer or
  receipt writer in such a probe (`runtime-residency-contract.spec.mjs`, a shrink-only ratchet).

### 1.2 Rigs (`lib/rig-registry.mjs`, `rigs/*.mjs`)

A rig is one scene, declared as data: `rigs/<id>.mjs` default-exports one frozen plain object, with no functions, no
imports and no I/O, so `loadRigs()` (`rig-registry.mjs:113`) can read every rig in a spec with no browser.
`validateRig` (`:139`) fails closed on:

- `id`; `tags` (at least one, each from `RIG_TAGS`, `:59`, add-only — 18 tags at this tree); `renderers` (`webgl`,
  `webgpu`).
- exactly one of `page` (a path under the origin), `url` (absolute; only the wave-end rigs use it) or `page: null`
  (no page renders the rig from data yet; the probe builds the scene itself).
- `camera`: `null` (the page's default view), the degrees form `{lon, lat, height, heading?, pitch?, roll?}`, or the
  ECEF form `{position, direction, up}`.
- `clock`: `null` or an ISO-8601 UTC instant.
- `viewport` `{width, height}`; `readiness` with `kind` `settleFrames` (`frames`) or `settleMs` (`ms`)
  (`READINESS_KINDS`, `:81`). Families add fields the probe reads (the polar rigs add `readiness.maxFrames` and
  `dwellMs`).
- `dials`: free-form per family. A stage piece declares which dials it can apply, and a probe refuses a rig with a
  dial it cannot apply rather than photograph a different scene under the rig's name (`rig-dial-unsupported`, e.g.
  `probe-polar-multi-plain.mjs:195-224`).
- optional `gate` (exactly one of `minChangedFraction` / `maxChangedFraction` with a `why`), `expectedMismatch`, and
  documentary fields such as `declaredBy` (the probe a scene was re-declared from).

`replayKeyFor` (`:309`) hashes only the fields that change what renders, so an annotation edit does not change a
key. `generateScenesJson` (`:396`) regenerates `scenes.json` byte-for-byte from the ten `wave-end` rigs, which is
how the wave-end capture suite and the registry are kept one source. The registry's size and per-tag counts are
pinned in `REGISTRY_CENSUS` at the top of `rig-registry.spec.mjs`; a rig that lands moves that census in the same
change.

A rig, for reference (`rigs/polar-plain-equator-mid.mjs`, abridged):

```js
export default Object.freeze({
  id: "polar-plain-equator-mid",
  tags: ["polar"],
  page: "Apps/CesiumViewer/index.html",
  renderers: ["webgl", "webgpu"],
  camera: { lon: 0, lat: 0, height: 3000000, heading: 0, pitch: -1.5707963267948966, roll: 0 },
  clock: "2026-05-19T18:00:00Z",
  dials: { terrain: "wgs84" },
  viewport: { width: 1280, height: 720 },
  readiness: { kind: "settleFrames", frames: 302, maxFrames: 1500, dwellMs: 2000 },
});
```

### 1.3 The capture seam (`lib/capture.mjs`)

`capture(rig, {BEFORE, AFTER}, options, dependencies)` (`capture.mjs:1876`) captures one rig or a rig set over two
origins, on every renderer each rig declares, in ONE browser, back to back, and computes every measurement in Node
after the browser has closed. There is no default origin (`capture-origin-absent`). Its output is a capture
manifest that carries no verdict: a rig's `gate` or `expectedMismatch` never reaches it, `validateManifest`
(`:1102`) rejects `PASS`/`FAIL` tokens, and `UNMEASURED` is a first-class cell state. The URL builder the probes
share is `captureUrlFor({rig, origin})` (`:425`), which resolves a rig's `page` or `url` and refuses a rig with
neither (`capture-rig-has-no-page`).

At this tree the only committed caller of `capture()` itself is `capture-seam.spec.mjs`; there is no capture CLI,
and Edge legs that used it composed a lane-local driver. Fourteen top-level probes import from it, all of them
`captureUrlFor` only (§4, `lib/capture.mjs` row).

### 1.4 Metrics (`lib/metrics/*.mjs`, `lib/image-diff.mjs`)

A metric is a pure function over decoded RGBA (`{width, height, data}`) with no I/O and no page access, so a spec
drives it with synthetic frames and a probe calls it after `decodePng(shot.buffer)`. `lib/image-diff.mjs`
(`diffImages`) is the one per-channel pixel diff. Metrics compute in Node, never in the page; a probe that measured
in the page has its arithmetic moved into a metric with a spec that runs the old in-page arithmetic beside it over
the same frame (the voxel, weather and globe harvests did this). Forty-two metrics exist at `7eeae0fbaa` (§4).

### 1.6 Contact sheets

`node Tools/visual-regression/contact-sheet.mjs --manifest <capture-manifest.json> --sheet-id <id>` renders one capture

### 1.7 The archive

A retired probe is MOVED to `Tools/visual-regression/archive/` with `git mv` and flipped to
`@status ARCHIVED-CANDIDATE`; deletion, if ever, is a later separate batch from a positive list (`R-2026-09-17-11`;
the six conditions are in [PROBE_KIT_PLAN_2026-09-17.md](PROBE_KIT_PLAN_2026-09-17.md) §4.2). The conclusion is

(polar, wgs84, c11, weather, cloud round 1 and globe at this tree), in the file's own `@supersededBy` / `@note` tags
where the harvest wrote them, and in the tables of the
[archive README](../Tools/visual-regression/archive/README.md). In the harvest its scenes are re-declared as rigs
before the move, so "re-run the archived probe" becomes "capture the rig". `@status ARCHIVED-CANDIDATE` takes a
file out of the live fleet wherever it sits (`fleetExemption`, `lib/probe-fleet-contract.mjs:1200`).

### 1.8 The guards and the landing rebaser

- `probe-fleet-contract.spec.mjs` is the fleet census. Since Batch 1574 its analyzer counts a probe that hands its
  launch to `runProbe` as a launching probe (`launchesThroughRuntime`, `lib/probe-fleet-contract.mjs:759`), so a
  family harvest no longer shrinks the census while the analyzer is unchanged.
- `lib/*-allowlist.mjs` files are shrink-only: a harvest removes the rows of the probes it migrated and never adds one.
- `REGISTRY_CENSUS` (rig counts), `RIG_TAGS` (tags) and the allowlists are edited by every family landing.
  `Tools/landing/rebase-shared.mjs` (Batch 1570; [Tools/landing/README.md](../Tools/landing/README.md)) takes a frozen
  lane patch and regenerates its hunks on those files against the current tip as their semantic union, refusing by
  name anything it cannot reproduce, so two families landing in sequence stop conflicting textually.

## 2. How a probe runs on the kit

### 2.1 From a rig name to a banked receipt

Using `probe-polar-multi-plain.mjs` (polar family, Batch 1562) as the rig-driven shape:

1. `node Tools/visual-regression/probe-polar-multi-plain.mjs --port 8094 --rigs polar-plain-equator-mid` — the
   descriptor declares `--rigs` through `args.extraOptions` (`probe-polar-multi-plain.mjs:410-422`).
2. The runtime parses the flags, refuses port 8080 (today by crashing with exit 1, `DX-96`, §2.3), preflights the served build on `http://localhost:8094` against
   the tree named by `--repository-root` (the working directory by default), takes the Edge slot and launches Edge.
3. `cells` loads the registry (`loadRigs`) and selects the named rigs: an unknown id is a caller error (exit 2),
   a dial the probe cannot apply a refusal (`rig-dial-unsupported`, exit 3).
4. Per rig and renderer: a fresh browser context sized to `rig.viewport`, `goto ${origin}/${rig.page}?renderer=…`,
   wait for the viewer, apply the rig in the page (terrain, clock, dials, camera, settle), wait `dwellMs`, strip the
   viewer widgets and refuse if anything still covers the canvas, then `captureElement` writes
   `<rig>-<renderer>-run<run>.png` (`:325-381`).
5. In Node: decode both legs and score them with `lib/metrics/polar-parity.mjs`.
6. The runtime writes `polar-multi-plain-report.json` (runtime envelope) and `-summary.md` under
   `Tools/visual-regression/output/polar-multi-plain/` and exits 0.

### 2.2 Worked example: BEFORE/AFTER on two served trees (`probe-texture-lifetime.mjs`, FW-06 Edge job 9b)

`probe-texture-lifetime.mjs` (landed in Batch 1578) is built from pieces: two rigs imported as data
(`globe-msaa4-resize-ladder`, `skybox-source-swap`), two step modules (`lib/globe-resize-steps.mjs`,
`lib/skybox-swap-steps.mjs`), the in-page census (`lib/gpu-texture-census.mjs`), the error gate and page diagnostics,
`captureUrlFor`, the widget strip, `captureElement`, `lib/image-diff.mjs` and `lib/metrics/corner-colour.mjs`, with
a declared `workBudgetMs` (`probe-texture-lifetime.mjs:430-452`). The seat's Edge executor ran it on 2026-10-09,
17:38-18:00 EDT, and banked the result at
`Tools/visual-regression/output/wave-end/audit-fix-wave-1/FW-06/job9b/` in the seat (gitignored output).

- **Two trees, two servers.** BEFORE was a seat Edge clone at the base tree, AFTER the lane clone at the frozen tree,
  each built in its own clone and served from it: `node server.js --serve-built --port 8094 --sandcastle-port 8095`
  (BEFORE) and `--port 8096 --sandcastle-port 8097` (AFTER). The seat's own tree is never served for an Edge leg
  (ORCHESTRATION_HANDBOOK.md §7, "Environment").
- **The command**, once per leg:

  ```bash
  node Tools/visual-regression/probe-texture-lifetime.mjs --serve-built --port <8094|8096> --scene resize,skybox \
    --runs 3 --repository-root <tree> --output <bank>/<BEFORE|AFTER>
  ```

  `--repository-root` makes the preflight compare the served bytes with THAT tree's `Build/`; `--output` puts the
  frames and the receipt in the bank instead of the clone's `output/`.
- **What landed in each leg's folder.** `resize-webgl-run0.png` … `skybox-webgpu-run2.png`, the probe's
  `<scene>-diff-run<N>.png`, `texture-lifetime-report.json` and `texture-lifetime-summary.md` (runtime envelope, so
  no separate `-runtime.json`). The AFTER report carries `servedBuildAssertion: "enforced"`, a `preflight` whose
  every artifact reads `match: true` with its disk and served md5, the `edgeSlot` lock path under the AFTER tree,
  one capture record per frame (`resize-webgl-run0`: `matchCount` 1, liveness `unobserved`, since a WebGL page arms
  no WebGPU gate), the probe's `scene` and `cells`, and `exitCode` 0.
- **What did not land.** Two earlier AFTER attempts errored after their cells were captured: one with
  `browser run 1 did not close before its deadline` (exit 2, `texture-lifetime-error.json`), one at the lifecycle's
  hard stop (exit 2, no record at all, and the slot lock left behind). Neither touched the banked receipt; both are
  in §5.

### 2.3 A refusal is not a failure

Exit 3 means the run's preconditions did not hold, so it has no standing to report a pass or a fail. Example from
the same evening (`…/FW-03b/job15b/after/multimaterial/polyline-multimaterial-refusal.json`): `outcome: "refused"`,
`refusal.reason: "multi-run-not-supported"` (the probe keys its receipt by device pixel ratio, so `--runs 3` would
drop two runs), `exitCode` 3, and the full runtime record (origin, options, preflight, slot) beside it; no receipt
was written. Read a refusal as "fix the precondition and run again", never as a soft red. The runtime's own refusal
ids: `port-8080-forbidden`, `served-build-preflight-failed`, `served-build-preflight-incomplete`,
`requested-origin-invalid`, `navigation-url-invalid`, `origin-mismatch`, `render-ready-absent`,
`render-ready-timeout`, `edge-slot-busy`, `capture-selector-ambiguous`, `capture-device-lost`,

## 3. Building a new probe from pieces (kit first)

**The procedure.** Answer each question from §4 before writing a line; stop at the first "yes" that covers the need.

1. **Is there a rig for the scene?** Search §4 "Rigs by tag". If not, declare one as data in `rigs/<id>.mjs` with a
   `@purpose` header, using a tag from `RIG_TAGS` (a new family needs a new tag, add-only), and move
   `REGISTRY_CENSUS` in `rig-registry.spec.mjs` in the same change.
2. **Is there a stage or step piece for the scene kind?** Search §4 "Kit pieces" (and §1.5). Reuse it; if it lacks
   one dial, add the dial to that piece with its spec case rather than applying it inside the probe.
3. **Is there a metric?** Search §4 "Metrics". Reuse it; compute in Node from the captured PNG.
4. **Is there already a probe on the runtime that captures the scene?** Search §4 "Probes on the runtime". Extend its
   scene table (a new rig id in its default set, or a new `--scene` entry) instead of writing a second probe.
5. **Only then write ONE new modular piece**: a `lib/` module (or `lib/metrics/` module) with one responsibility, a
   `@purpose` / `@status ACTIVE` header, pure functions where possible (page functions exported as functions or
   source text, since `page.evaluate` cannot close over Node imports), and a Node spec with an inertness mutant
   (make the rule unreachable, `if (false && …)`, and show the spec goes red). Never a bespoke probe that launches its
   own browser, and never a private driver.
6. **The probe itself is a descriptor**: `@purpose`, `@status`, `@runtime lib/probe-runtime.mjs` in the header;
   rigs imported as data or loaded from the registry; `captureUrlFor` for the page URL; the widget strip before an
   element capture; `captureElement` for every frame; metrics in Node; `workBudgetMs` declared; the call guarded by
   `isEntryPoint`. `probe-texture-lifetime.mjs` is a compact reference for every one of these.
7. **Same change**: regenerate §4 (`--write`), give the spec a runner home (`package.json`
   `test-visual-regression-node` for a browser-free kit spec; lanes name it and the seat adds it at landing), and
   let the seat regenerate `migration_doc/TOOLING_CATALOG.md` at landing.

**Censuses and allowlists.** A family harvest moves `REGISTRY_CENSUS` and `RIG_TAGS` up and shrinks the fleet and
residency allowlists by the probes it migrated; it never adds an allowlist row. Lanes freeze against an older base,
so at landing the seat runs `Tools/landing/rebase-shared.mjs` over the frozen patch to rebase exactly those hunks onto
the tip (§1.8).

**The Edge executor pattern.** Lanes do not run browsers unless their brief says so. A lane that needs an Edge
measurement writes a job sheet (`_lane-out/EDGE_LEG_<id>.md`, e.g. FW-06's): the two trees and how each is built
and served, the exact command per leg with `--repository-root` and `--output`, the pre-registered bands each cell
must meet and the condition that disconfirms the fix, and the stop rules. The seat's Edge executor runs it, one job
at a time on governed ports (`R-2026-09-02-1`), records the sheet's md5 before the first run, asserts served md5 ==
disk md5 on both trees, and banks a `RECEIPT.md` with the frames under `output/wave-end/<wave>/<lane>/`. Write the
sheet as an executable recipe — two trees, md5 pairs on both, every command in full
([WORKER_ISOLATION_AND_BRANCH_HANDOFF.md](WORKER_ISOLATION_AND_BRANCH_HANDOFF.md) §8j) — because a recipe that needs
judgement at run time has needed several verifier rounds before it ran.

## 5. Known gaps and the kit lanes

**The five kit lanes** (planned by the seat on 2026-10-09; none has a landing packet at this writing):

- **KIT-1** — one strip-then-refuse function for the viewer chrome (one refusal id where five exist today, a
  leftover test decided by the browser's hit test rather than rectangle overlap, the loading indicator and the dev-UI
  toolbar covered), and one rig-page URL / open-viewer piece, with the family copies routed onto them.
- **KIT-2** — a fill-after-cells driver: probe receipts become the AFTER cells of a capture manifest, the contact
  sheet is banked where the wave-end gate reads it, and size mismatches are handled before a pair is scored.
- **KIT-3** — the `capture()` rig seam: a stage registry (camera, clock, dials by declared table, readiness), the
  chrome strip through KIT-1, a same-task canvas read, the renderer-axis manifest fix, and a capture CLI.
- **KIT-4** — metrics consolidation: the channel-sum copies onto `lib/metrics/rgb-sum.mjs`, the wgs84 non-black
  percentage from its integer fields, one size-mismatch shape in the kit engines.
- **KIT-5** — runtime hygiene: receipt timing, `url` and `capturedAt` on every capture record, one PNG-banking
  primitive, a path-decided guard on frame writes into the shared `output/` root, the port refusal reused by the
  c11 probes, a source-identity producer for the wave-end gate, and an Edge-job runner; phase B declares measured
  `workBudgetMs` for the probes that have none.

**Gaps measured at this tree:**

- **`capture()` checks both origins against one tree.** `capture.mjs:1893-1903` preflights the BEFORE and the AFTER
  origin with the same `descriptor.repositoryRoot` (resolved once, `:623`), so a BEFORE leg served from another tree
  fails the served-build check against the AFTER tree's bytes. FW-04's Edge job wrapped the preflight per tree by
  hand; per-slot roots belong with KIT-3's capture CLI.
- **A hard stop writes no record.** When the lifecycle's hard-stop grace expires, `hardExit`
  (`lib/probe-lifecycle.mjs:217-232`) writes one line to stderr and exits 2: no `-error.json`, and the Edge-slot lock
  stays in `output/` until a later acquire reclaims it. FW-06's job 9b lost one AFTER attempt this way (§2.2). A
  candidate for KIT-5.
- **A parse-time refusal crashes (`DX-96`, OPEN, [DEFERRED_WORK.md](DEFERRED_WORK.md) "DX-96").** A refusal or
  error raised inside `parseProbeArgs` (port 8080, an unknown flag) leaves `options` null, `buildRuntimeReceipt`
  reads `options.servedBuild` off it (`probe-runtime.mjs:833`, from `:1224`), and `runProbe` rejects: no record, exit
  1 instead of 3 or 2 (§2.3). Filed 2026-09-13 against `DX-01`'s file and not fixed since; a natural KIT-5 item
  (runtime hygiene).
- **Run indices start at 0.** Both run loops count from 0 (`probe-runtime.mjs:1129`,
  `lib/probe-lifecycle-run.mjs:219`), so the first run's frames are named `…-run0.png`; a job sheet that named
  `run1` for a one-run job pointed at frames that were never written (FW-02's Edge re-run). Name runs from the receipt's
  capture records, not by convention.
- **The Edge-slot lock is per tree.** The lock path is joined to `--repository-root` (`probe-runtime.mjs:1108-1111`,
  `:1123`), so two runs against two trees hold two different locks. The one-job-at-a-time rule across trees is held
  by the executor, not by the lock (FW-06 job 9b's AFTER lock sat in the lane clone).
- **The fleet contract counts runtime probes (landed).** `launchesThroughRuntime` (Batch 1574) closed the census
  defect in which every harvested family shrank the launching count.
- **39 of the 86 runtime probes take the pre-lifecycle path** (no `workBudgetMs` in their code; the WCS leg inherits
  the EDR leg's budget through `sweepDescriptor`), among them the polar probe and all ten clustered and all ten
  globe probes. KIT-5 phase B declares measured budgets for them.
- **One kit piece has no consumer that can load it.** `lib/godray-near-ceiling.mjs` reads 0 / 0 / 0 in §4 because
  its one consumer, `probe-godray-energy-law.mjs:77`, imports it as `../lib/godray-near-ceiling.mjs`, which resolves
  to `Tools/lib/`, where no such file exists, so that probe fails at module load; `godray-energy-law.spec.mjs:1321`
  asserts the same path as source text. It is the only relative import under `Tools/visual-regression/` that
  resolves to a missing file at this tree. `lib/globe-clip-scene.mjs` (FW-04, Batch 1582) also reads 0 / 0 / 0, for
  a different reason: nothing in the tree imports it yet; its header calls it the cell body that stages a globe
  clipping-plane rig for `lib/capture.mjs`, so its caller is a `capture()` run that is not in the tree.
- **Five `lib/` modules have no `@purpose` header**, among them the kit's own `lib/strip-viewer-widgets.mjs`
  (§4 shows each as "no `@purpose` header").
- **26 runtime probes link no rig** by the four rules in §4: they open a harness page (`probe-ar002-*`,
  `probe-ar757-*`), the Weather Inspector Sandcastle demo (eight cloud demo probes and `probe-weather-presets.mjs`),
  or build their scene inline on CesiumViewer or a Sandcastle2 demo. Each is a candidate for a rig declaration the
  next time its family is touched.
- **Four runtime probes have no spec that imports them**: `probe-ar002-per-tile-credits.mjs`,
  `probe-ar757-derived-origin.mjs`, `probe-buffer-polyline-meters-width.mjs` and `probe-eye-cartographic-frame.mjs`
  (each is named in a spec's text, but none is driven through its descriptor).
- **537 `probe-*.mjs` still launch Edge themselves** at this tree (§4, direct-launch table, read by behaviour:
  a Playwright import and a `.launch(` call); the harvest continues family by family under `DX-108`. The fleet
  contract's census line reads 538, because its analyzer also counts `probe-q141-pick-readback.mjs`, which loads
  Playwright through `require()`; §4 lists that file under "launch nothing detectable".
- **The old template advice is superseded.** CLAUDE.md Principle 8 and the `DEBUGGING_GUIDE.md` templates table still
  name `probe-saved-view.mjs` as the template to copy; under the kit rule a new probe is built from rigs, stage pieces,
  metrics and the runtime instead.
