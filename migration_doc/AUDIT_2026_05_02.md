# Cross-Coupling Audit — 2026-05-02

**Scope:** 5-cluster parallel audit of every feature in `migration_doc/FEATURE_INVENTORY.md`, comparing implementation versus expected cross-feature coupling. Goal: surface unfinished work and bad implementations not yet documented in `DEFERRED_WORK.md` / `FUTURE_RESEARCH_2026_05_01.md`.

**Method:** Five subagents read actual code under `packages/engine/Source/Renderer/WebGPU/`, `Source/Shaders/WebGPU/`, `Source/Scene/`, and design docs, then identified gaps where features that SHOULD interact don't, or where the documented status is stale.

**Total findings:** ~110 gaps across 5 clusters. This doc keeps the highest-impact ones and groups them by severity. Status-doc corrections (stale DEFERRED_WORK entries) are listed at the end.

---

## Summary by severity

- **BREAKING (15)** — visible regression in user-facing scenarios (silent feature breaks, wrong output, missing functionality with no warning).
- **PARTIAL (35)** — feature works in narrow conditions but is incomplete; visible in adjacent scenarios.
- **LATENT (24)** — works today, future risk; resource leaks, fragility, dead orphan code.
- **STALE STATUS (8)** — documentation lies about current state; misleads scoping.

### ~~A.4 Classification primitives broken in 2D / Columbus / Morphing modes~~ — RESOLVED for GroundPrimitive (Batches 150 + 156 + 164); Vector3DTile* parity deferred behind demand

**Inventory:** §A.2 ground/classification primitives + §C.1 BUG-3 (smoke test pending).
**Bug:** Classification renderers don't apply 2D-jitter or Columbus-mode position transforms. Visual: classification volumes wander or disappear in non-3D scene modes.
**Resolution:**

- Batch 150 added a conservative silent-skip gate to four renderers in non-3D scene modes (`WebGPUGroundPrimitiveRenderer`, `WebGPUVector3DTilePrimitiveRenderer`, `WebGPUVector3DTileClampedPolylinesRenderer`, `WebGPUVector3DTilePolylinesRenderer`).
- Batch 156 narrowed the gate on `WebGPUGroundPrimitiveRenderer` to MORPHING-only: SCENE2D + COLUMBUS_VIEW now select the per-vertex `position2DHigh/Low` attributes that `PrimitivePipeline.js:175-208` produces alongside the 3D positions. Combined with `uniformState.view × projection` (auto-2D in non-3D modes) and `camera.positionWC` (CesiumJS auto-adjusts to active scene mode), the existing RTE math at `colorVS` produces correct classification volumes without any shader changes. Cache invalidation via `cache.positionSourceKey` rebuilds the vertex buffer when the scene mode flips.
- **Batch 164 closed the MORPHING leaf for `WebGPUGroundPrimitiveRenderer`:** dedicated `morphColorVS` entry point at [WebGPUGroundPrimitiveRenderer.js:221](../packages/engine/Source/Renderer/WebGPU/WebGPUGroundPrimitiveRenderer.js#L221) projects both 3D and 2D EC positions and lerps via `frameState.morphTime` (UBO float 84). Parallel attribute layout (3D at locations 0/1, 2D at 2/3) bound only on MORPHING frames. UBO grew 256→384 to fit the morphFlags slot.
- `WebGPUGroundPolylineRenderer` already correct in all four scene modes via parallel-attribute-set + dedicated morph pipeline (Batches 116/117 era).

**`Vector3DTile*` clarification (Batch 158):** `Vector3DTilePrimitive` / `Vector3DTilePolylines` / `Vector3DTileClampedPolylines` carry RTC-relative positions tied to the tileset's `_center`; they do NOT have `position2DHigh/Low` attribute pairs (verified across `Vector3DTilePrimitive.js`, `Vector3DTilePolylines.js`, `Vector3DTileClampedPolylines.js`). WebGL's path doesn't check scene mode for these classifiers either — it just emits the commands and lets the projection matrix do whatever, producing wandering volumes in 2D / CV (the same failure mode the audit cited as a WebGPU "bug"). Our silent-skip gate is therefore BETTER than upstream WebGL behavior, not worse, for the `Vector3DTile*` family. **Lifting the `Vector3DTile*` gate would be a regression** unless paired with a CPU- or shader-side projection of the RTC-relative 3D positions into the active 2D/CV map space — the ~80 LOC parallel-attribute or projection-matrix work the audit estimated. 3D-Tiles content is typically only viewed in SCENE3D in production, so the deferred work has low practical impact.

**Remaining (deferred):** Vector3DTile* full 2D/CV/Morph support — tracked as `NEW-CLASSIFIER-2D-CV-MORPH` in DEFERRED_WORK. Deferred behind real demand from a Vector3DTiles-in-2D-mode use case.

### ~~A.5 TAA velocity for skinned/morphed/instanced models is wrong~~ — RESOLVED (Batches 130 + 134, re-audit Batch 147)

Re-audit verification (Batch 147): bindings distinct, structurally-compatible morph metadata (targetCount/vertexCount are asset-bound and identical across frames), shared `morphDeltas[idx]` is correct (per-target vertex offsets are vertex attributes, not animation state — only the WEIGHTS change). ### ~~A.10 Sun renders at full brightness through Earth (no horizon test)~~ — RESOLVED (commit a837a9ad79, re-audit Batch 149)

**Inventory:** §B.3 `WebGPUSunRenderer` SHIPPED.
**Resolution:** The horizon test shipped in the same commit that wrote this audit doc (`a837a9ad79` — "Cross-coupling audit (2026-05-02) + 6 audit-driven fixes"), so the audit description is stale-by-construction.

Current implementation (`Sun.wgsl:45-66`) uses the audit's suggested `dot(sunDirWC, cameraUpWC)` cull approach:

```wgsl
let cameraECEF = u.encodedCameraHigh + u.encodedCameraLow;
let cameraECEFLen = length(cameraECEF);
if (cameraECEFLen > 1.0) {
  let cameraUp = cameraECEF / cameraECEFLen;
  let sunDir = normalize(positionRTE);
  let sunUpDot = dot(sunDir, cameraUp);
  if (sunUpDot < -0.06) {
    // Sun is well below horizon; collapse to clip-space corner
    // out of [-1, 1] so all four corners are clipped.
    clipPos = vec4<f32>(2.0, 2.0, 2.0, 1.0);
  }
}
```

The threshold (-0.06 ≈ 3.4° below horizon) gives a soft margin for atmospheric refraction. Surface-level cameras correctly gate the sun when below local horizon; orbital cameras gate when looking through Earth at the antipodal sun. The `cameraECEFLen > 1.0` guard avoids dividing by zero at the planet origin.

Re-audit verification (Batch 149): test correctly gates sun when looking at antipodal sun from orbit (sunDir and cameraUp anti-parallel → dot ≈ -1 → gated). Surface camera at sunset (sun just below horizon) correctly transitions through the soft band. The implementation matches the audit's recommended fix.

### ~~B.8 AGI_articulations + node-level transforms silently dropped~~ — RESOLVED (Batch 152, corrected Batch 154)

**Resolution:** `WebGPUModelRenderer.js` now computes `nodeModelMatrix = sceneGraphMatrix × runtimeNode.computedTransform` per runtime node and threads it through both the camera UBO (per-node `cameraBuffer` + `cameraBG` lazy-allocated on the existing `cache.nodes[nodeIdx]` slot) and the material UBO (`material.modelMatrix` for the FS world-space reconstructions at lines 1600/2016/2029/2072/2233 of `ModelPBRComplete.wgsl`). Identity-transform nodes (the common single-node case) skip the per-node camera resource allocation and reuse `cache.cameraBG`.

`computedTransform = transformToRoot × transform` (initialized in `ModelRuntimeNode.initialize()`, kept current by `ModelMatrixUpdateStage`). Articulated rigs (AGI_articulations) and non-skinned animated rigs now render at their correct world position.

**Follow-up:** TAA velocity for articulated nodes still uses the model-level `cache.prevModelMatrix`; per-node prev-matrix tracking is tracked as `NEW-MODEL-NODE-TRANSFORMS-PREV` for animated articulations under TAA. Static articulations (set once, then locked) work today.
