# Cross-Coupling Audit — 2026-05-02

**Scope:** 5-cluster parallel audit of every feature in `migration_doc/FEATURE_INVENTORY.md`, comparing implementation versus expected cross-feature coupling. Goal: surface unfinished work and bad implementations not yet documented in `DEFERRED_WORK.md` / `FUTURE_RESEARCH_2026_05_01.md`.

**Method:** Five subagents read actual code under `packages/engine/Source/Renderer/WebGPU/`, `Source/Shaders/WebGPU/`, `Source/Scene/`, and design docs, then identified gaps where features that SHOULD interact don't, or where the documented status is stale.

**Total findings:** ~110 gaps across 5 clusters. This doc keeps the highest-impact ones and groups them by severity. Status-doc corrections (stale DEFERRED_WORK entries) are listed at the end.

---

## Summary by severity

- **BREAKING (15)** — visible regression in user-facing scenarios (silent feature breaks, wrong output, missing functionality with no warning).
- **PARTIAL (35)** — feature works in narrow conditions but is incomplete; visible in adjacent scenarios.
- **LATENT (24)** — works today, future risk; resource leaks, fragility, dead orphan code.
- **STALE STATUS (8)** — documentation lies about current state; misleads scoping.

### ~~A.5 TAA velocity for skinned/morphed/instanced models is wrong~~ — RESOLVED (Batches 130 + 134, re-audit Batch 147)

**Inventory:** §B.5 WebGPUTAAEffect SHIPPED Slice 1+2.
**Resolution:** The bug as originally written was already fixed before this audit landed. The fix runs the morph → skin → instance pipeline TWICE in `ModelPBRComplete.wgsl:716-770`: once for `positionMC` using current-frame data (joints, morph weights, instance transforms), and a second time for `prevPositionMC` using prev-frame data (`previousJointMatrices` at @group(2) @binding(4), `previousMorphWeights` at binding 5, `previousInstanceTransforms` at binding 6). The downstream velocity computation then takes `material.previousModelMatrix * vec4(prevPositionMC, 1.0)` — using the correctly-deformed prev-frame position, NOT the current-frame `positionMC` the audit cited.

The audit's line numbers (599-613) refer to the pre-Batches-130/134 shader; the current implementation is at lines 716-770 with `// Audit A.5 (Batch 130) + re-review (Batch 134)` in the comment block.

JS-side wiring (`WebGPUModelRenderer.js`):

- `nodeCache.prevPackedJointMatrices` mirror + `prevJointBuffer` GPU buffer (`ensurePrevJointMatricesBuffer`); per-frame `prevPackedJointMatrices.set(packedJointMatrices)` BEFORE `updatePackedJointMatrices(...)` mutates the current matrices, then `writeBuffer(prevJointBuffer, ...)` followed by `writeBuffer(jointBuffer, ...)`.
- `prevMorphWeightBuffer` (NEW-TAA-MORPH-PREV) and `prevInstanceTransforms` (NEW-TAA-INSTANCE-PREV) bound at the same step.
- `cache.prevModelMatrix` updated at the END of `update()` so every primitive's pack call sees the same prev-frame matrix.
- First-frame fallback: prev buffers alias their current counterparts → prev = current → zero velocity, equivalent to "no history" which TAA's first-frame logic already handles.

Re-audit verification (Batch 147): bindings distinct, structurally-compatible morph metadata (targetCount/vertexCount are asset-bound and identical across frames), shared `morphDeltas[idx]` is correct (per-target vertex offsets are vertex attributes, not animation state — only the WEIGHTS change). No regression to address.

### ~~A.10 Sun renders at full brightness through Earth (no horizon test)~~ — RESOLVED (commit a837a9ad79, re-audit Batch 149)

**Inventory:** §B.3 `WebGPUSunRenderer` SHIPPED.
**Resolution:** The horizon test shipped in the same commit that wrote this audit doc (`a837a9ad79` — "Cross-coupling audit (2026-05-02) + 6 audit-driven fixes"), so the audit description is stale-by-construction.

Current implementation (`Sun.wgsl:45-66`) uses the audit's suggested `dot(sunDirWC, cameraUpWC)` cull approach:

```wgsl
let cameraECEF = u.encodedCameraHigh + u.encodedCameraLow;
let cameraECEFLen = length(cameraECEF);
if (cameraECEFLen > 1.0) {
  let cameraUp = cameraECEF / cameraECEFLen;
  let sunDir = normalize(positionRTE);
  let sunUpDot = dot(sunDir, cameraUp);
  if (sunUpDot < -0.06) {
    // Sun is well below horizon; collapse to clip-space corner
    // out of [-1, 1] so all four corners are clipped.
    clipPos = vec4<f32>(2.0, 2.0, 2.0, 1.0);
  }
}
```

The threshold (-0.06 ≈ 3.4° below horizon) gives a soft margin for atmospheric refraction. Surface-level cameras correctly gate the sun when below local horizon; orbital cameras gate when looking through Earth at the antipodal sun. The `cameraECEFLen > 1.0` guard avoids dividing by zero at the planet origin.

Re-audit verification (Batch 149): test correctly gates sun when looking at antipodal sun from orbit (sunDir and cameraUp anti-parallel → dot ≈ -1 → gated). Surface camera at sunset (sun just below horizon) correctly transitions through the soft band. The implementation matches the audit's recommended fix.

### ~~A.15 `Cesium3DTileStyle.applyStyle()` has no WebGPU consumer in Model batch path~~ NOT A BUG (re-audit 2026-05-03, Batch 130)
**Original claim:** `WebGPUModelRenderer.js` has no `applyStyle`/`batchTable`/`featureColor`/`featureShow` references, so style updates are unwired.
**Re-audit finding:** The grep was true but the diagnosis was wrong. The flow IS wired -- it just routes through the `BatchTexture` intermediary rather than direct strings in the renderer file:

1. `tileset.style = ...` -> `Cesium3DTileStyleEngine.applyStyle(tileset)` per frame
2. Per tile: `Model3DTileContent.applyStyle(style)` -> `model.style = style` -> `Model.applyStyle(style)`
3. `ModelFeatureTable.applyStyle(style)` evaluates per-feature color/show and calls `BatchTexture.setColor(i, c)` / `setShow(i, s)`
4. `BatchTexture` flips `_batchValuesDirty = true`
5. WebGPU `WebGPUModelFeatureId.ensureFeatureIdResources` checks `_batchValuesDirty` and re-uploads the batch GPU texture
6. `ModelPBRComplete.wgsl` `lookupBatchColor()` reads it; the FS multiplies the final color by `batchColor.rgb` and discards on `batchColor.a < 0.004`

Audit B.2 (Batch 130) closed the last remaining gap (vertex-attribute feature ID path) so b3dm tilesets reach the batch lookup. End-to-end style propagation works on WebGPU as of Batch 130; no separate fix required.
