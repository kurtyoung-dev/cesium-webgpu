# Cross-Coupling Audit — 2026-05-02

**Scope:** 5-cluster parallel audit of every feature in `migration_doc/FEATURE_INVENTORY.md`, comparing implementation versus expected cross-feature coupling. Goal: surface unfinished work and bad implementations not yet documented in `DEFERRED_WORK.md` / `FUTURE_RESEARCH_2026_05_01.md`.

**Method:** Five subagents read actual code under `packages/engine/Source/Renderer/WebGPU/`, `Source/Shaders/WebGPU/`, `Source/Scene/`, and design docs, then identified gaps where features that SHOULD interact don't, or where the documented status is stale.

**Total findings:** ~110 gaps across 5 clusters. This doc keeps the highest-impact ones and groups them by severity. Status-doc corrections (stale DEFERRED_WORK entries) are listed at the end.

---

## Summary by severity

- **BREAKING (15)** — visible regression in user-facing scenarios (silent feature breaks, wrong output, missing functionality with no warning).
- **PARTIAL (35)** — feature works in narrow conditions but is incomplete; visible in adjacent scenarios.
- **LATENT (24)** — works today, future risk; resource leaks, fragility, dead orphan code.
- **STALE STATUS (8)** — documentation lies about current state; misleads scoping.

## A. BREAKING FINDINGS

### A.1 GlobeTranslucency `executeBatchTranslucent` drops all derived commands beyond `[0]`
**Inventory:** §B.3 `WebGPUGlobeTranslucencyState` — listed SHIPPED.
**Bug:** `executeBatchTranslucent()` in `WebGPUGlobeTranslucencyState.ts` only iterates the first derived command, dropping any subsequent translucent passes. Globe translucency renders the wrong thing for any scene needing more than one derived pass.
**Fix scope:** Iterate all derived commands; ~10 LOC.

### A.2 InvertClassification stencil-write pipeline absent post-ADR-2026-04-28
**Inventory:** §B.3 `WebGPUInvertClassification` — SHIPPED.
**Bug:** ADR-2026-04-28 made classifiers depth-sample-only (no stencil write). But `WebGPUInvertClassification` requires stencil writes from a `CESIUM_3D_TILE_CLASSIFICATION_IGNORE_SHOW` redirect. The producer no longer exists; the consumer's `_invertClassStencilReady` flag flips true without proof. End-to-end InvertClassification produces wrong output.
**Fix scope:** Either restore a stencil-write classifier variant or remove InvertClassification's stencil-gated fast-path. Architecture decision needed.

### A.3 Vector3DTilePrimitive `BOTH` only emits one pass
**Inventory:** §A.2 ClassificationType.BOTH on Vector3DTile.
**Bug:** When `classificationType === BOTH` (TERRAIN + 3D_TILE), WebGL emits two commands (one per Pass). WebGPU emits only one of the two, so a vector tile with `BOTH` classification only classifies on ONE of the two surfaces.
**Fix scope:** Mirror WebGL pass emission; ~15 LOC.

### A.4 Classification primitives broken in 2D / Columbus / Morphing modes
**Inventory:** §A.2 ground/classification primitives + §C.1 BUG-3 (smoke test pending).
**Bug:** Classification renderers don't apply 2D-jitter or Columbus-mode position transforms. Visual: classification volumes wander or disappear in non-3D scene modes.
**Fix scope:** Plumb scene-mode transform through classification UBOs; ~30 LOC.

### A.5 TAA velocity for skinned/morphed/instanced models is wrong
**Inventory:** §B.5 WebGPUTAAEffect SHIPPED Slice 1+2.
**Bug:** `ModelPBRComplete.wgsl:599-613` computes `worldPosPrevious = previousModelMatrix * vec4(positionMC, 1.0)` AFTER morph/skin/instance have mutated `positionMC`. So velocity is computed against deformed-current-frame position multiplied by previous-frame rigid transform — produces phantom motion vectors on every animated model. TAA ghosts visibly on character animation.
**Fix scope:** Run morph/skin/instance pipeline twice in VS (current vs previous joint matrices + previous morph weights + previous instance transforms) OR capture `prevPositionMC` as a separate vertex output. Significant; ~80 LOC + per-Model UB shape change.

### A.6 Models lack clipping-plane and clipping-polygon support entirely
**Inventory:** §A.3 ModelClippingPlanesPipelineStage — listed.
**Bug:** `ModelPBRComplete.wgsl:447` declares `clippingPlaneTex` at `@group(3) @binding(3)` but it's NEVER SAMPLED in `fragmentMain`. `clippingPlaneCount` field exists in `EffectsUniforms` but no clipping branch. Polygons aren't even bound. `model.clippingPlanes = ...` does nothing on WebGPU.
**Fix scope:** Port `Shaders/Model/ModelClippingPlanesStageFS.glsl` to a WGSL inline branch. Wire polygons SDF binding into Effects BGL. ~80 LOC.

### A.7 CustomShader API silent no-op on WebGPU
**Inventory:** §A.3 CustomShader, CustomShaderMode.
**Bug:** `WebGPUModelRenderer.js` has zero references to `CustomShader`. `Model.js:3142` short-circuits the WebGL `pushDrawCommands` path on WebGPU, bypassing `CustomShaderPipelineStage`. There's no WebGPU equivalent stage. User code in `model.customShader` is silently swallowed.
**Fix scope:** At minimum, `oneTimeWarning` when `model.customShader` is set on WebGPU. Long-term, WGSL CustomShader API parallel to GLSL one. ~5 LOC for warning, ~200 LOC for full WGSL surface.

### A.8 `model.classificationType` ignored on WebGPU
**Inventory:** §A.3 Model.classificationType / ClassificationModelDrawCommand.
**Bug:** `WebGPUModelRenderer.js` never inspects `classificationType`. Models loaded with `classificationType: TERRAIN` render as floating models instead of classifying onto terrain.
**Fix scope:** New `WebGPUClassificationModelRenderer` analogous to `WebGPUVector3DTilePrimitiveRenderer`. ~300 LOC.

### A.9 Image-Based Lighting on WebGPU is "split-sum approximation in name only"
**Inventory:** §B.3 `WebGPUImageBasedLighting` SHIPPED.
**Bug:** No environment cubemap is bound to the model material BGL. `ambientColor` is hardcoded to `vec3(0.2)` in `WebGPUModelRenderer.js:592-594`. `iblMaxMipLevel` is uploaded but only scales an attenuation factor — never used to sample anything. SH coefficient flag exists but is never sampled. PBR materials with authored env maps render with flat ambient.
**Fix scope:** Add `cubemap` + `cubemapSampler` bindings to material BGL; upload `_specularEnvironmentMapAtlas` cubemap; replace hardcoded ambient with `textureSampleLevel(envCube, sampler, R, lod)`. Add 9-coefficient SH UBO + `evalSH(N)`. ~120 LOC.

### A.10 Sun renders at full brightness through Earth (no horizon test)
**Inventory:** §B.3 `WebGPUSunRenderer` SHIPPED.
**Bug:** `Sun.wgsl:50-59` emits texture+glow with no depth comparison and no horizon gate. CELESTIAL §4.1 listed this as a Phase 2 sub-bullet; Phase 2 shipped without it. Sun is visible through Earth at night view-from-orbit.
**Fix scope:** Add depth test against scene depth OR `dot(sunDirWC, cameraUpWC)` cull. ~10 LOC.

### A.11 GodRayEffect is fully orphaned — registered nowhere
**Inventory:** §B.5 GodRayEffect SHIPPED.
**Bug:** `setSunScreenUV` has only doc-comment hits; no production code constructs or registers a `GodRayEffect`. No `pipeline.addGodRay()`, no entry in `WebGPUPostProcessStageCollection`. Compiles into bundle but dead at runtime.
**Fix scope:** Add `pipeline.addGodRay()` factory + `configureWebGPUPostProcessPipeline` branch consuming `scene.postProcessStages.godRay`. ~30 LOC.

### A.12 DynamicEnvironmentMapManager allocates cubemap but never renders into it
**Inventory:** §B.3 WebGPUDynamicEnvironmentMapManager SHIPPED.
**Bug:** `WebGPUDynamicEnvironmentMapManager.ts:133-154` writes `(128, 128, 128, 255)` to all 6 faces ONCE on first update. No scene capture pass, no IBL prefilter. PBR shaders consuming the cubemap sample flat 50% grey for all reflections.
**Fix scope:** Wire 6-face render-to-cubemap pass + `WebGPUIBLPipeline.generateIBLMaps()`. ~150 LOC.

### A.13 User-defined `PostProcessStage` and `PostProcessStageComposite` silent no-op
**Inventory:** §A.7 PostProcessStage user API.
**Bug:** `WebGPUPostProcessStageCollection.updateWebGPUPostProcessStages` only reads named built-in slots (fxaa, bloom, ambientOcclusion, etc.). Never iterates `collection._stages` where user `add()` calls land. User custom GLSL stages silently swallowed.
**Fix scope:** Walk `collection._stages`; for unknown names emit `oneTimeWarning` ("custom user stages not yet supported on WebGPU"). Long-term, accept `wgslFragmentShader` option. ~20 LOC for warning.

### A.14 Billboard / Label / Point / Polyline drop `distanceDisplayCondition` / `translucencyByDistance` / `pixelOffsetScaleByDistance` / clampToGround depth check
**Inventory:** §A.5 collections + §A.6 entity graphics distance attributes.
**Bug:** WebGL pushes `EYE_DISTANCE_TRANSLUCENCY`, `EYE_DISTANCE_PIXEL_OFFSET`, `DISTANCE_DISPLAY_CONDITION`, `VS_THREE_POINT_DEPTH_CHECK` defines onto its GLSL. WGSL shaders only handle `DISABLE_DEPTH_DISTANCE` + `SPLIT_ENABLED`. Setting `billboard.distanceDisplayCondition` does nothing on WebGPU. KML/GeoJSON entities render at all distances.
**Fix scope:** Port the four VS branches into BillboardCollection.wgsl, PointPrimitiveColor.wgsl, PolylineCollection.wgsl, label SDF. Add four `ShaderDefine` bits. Per-attribute data is already uploaded by JS side. ~150 LOC across 4 shaders.

### A.15 `Cesium3DTileStyle.applyStyle()` has no WebGPU consumer in Model batch path
**Inventory:** §A.2 3D Tile styling.
**Bug:** `WebGPUModelRenderer.js` has no `applyStyle`/`batchTable`/`featureColor`/`featureShow` references. Setting `tileset.style = new Cesium3DTileStyle({color: "color('red')"})` produces no visual change on WebGPU. The C-R1-TILE-BATCH and C-R9-MODEL-FEATURE-PICK entries describe pieces; the broader runtime style → batch table CPU upload → fragment color override flow is unwired.
**Fix scope:** New entry in DEFERRED_WORK bundling all three under user-facing description. Implementation: route `Cesium3DTileBatchTable` per-feature color/show into a per-tile storage buffer consumed by Model FS. ~250 LOC.

## B. PARTIAL FINDINGS (top 20 of ~35)

### B.1 Per-feature `Cesium3DTileFeature.show = false` ignored by classifiers
Vector3DTile classifiers have no `batchShow` storage buffer. WebGL packs `_showAlphaProperties`. **Fix:** Add `batchShow: array<f32>` to each classifier; multiply `o.col.a` in VS, discard when 0. ~30 LOC × 3.

### B.2 Per-feature pick texture-only path — vertex-attribute path missing (B3DM common)
`ModelPBRComplete.wgsl:1915-1929` gates per-feature pick on `FLAG_HAS_FEATURE_ID_TEXTURE`. B3DM uses `_BATCHID` vertex attribute predominantly. C-R9 says "blocked on b3dm rendering" — but it's MORE blocked: even when b3dm renders, vertex-attribute pick has no path. **Fix:** Wire `_BATCHID` vertex attribute → `flat`-interpolated FS varying → batch lookup. ~50 LOC.

### B.3 KHR_lights_punctual hardcoded "1 sun + ambient"
`LightUniforms` carries only `sunDirectionEC/sunColor/sunIntensity` + ambient. No light array. KHR_lights_punctual data parsed but never sent to FS. Model viewers / lit interiors render with completely wrong lighting. **Fix:** Add `LightUniforms.punctualLights: array<PunctualLight, N>` (N=8). ~100 LOC.

### B.4 5 default placeholder textures bound on every Model draw even when KHR extensions inactive
22 texture views bound per primitive even when KHR FLAGs are 0. Cost on every fragment. **Fix:** Two materialBGL variants — with/without KHR slots. ~40 LOC.

### B.5 NEW-KHR-ANISO-TANGENT — `tangentEC` IS plumbed; deferred-work prerequisite is stale
`ModelPBRComplete.wgsl:487/506/596-597` already computes `tangentEC` and uses it for clearcoat. Anisotropy at line 1497 just doesn't read it (uses `viewRight`). 1-2 line fix, not the multi-session refactor implied. **Fix:** Update DEFERRED_WORK; swap `viewRight` for `input.tangentEC` rotated by `aniRotation`.

### B.6 `drillPick` on WebGPU returns stale prior-frame results
`WebGPUPickFramebuffer.end()` always returns previous-frame pixels. `Picking.drillPick` calls `pick()` synchronously in a loop; each iteration sees the same prior-frame data. drillPick returns garbage. **Fix:** `drillPickAsync` API + force `device.queue.onSubmittedWorkDone()` between iterations on synchronous path. ~50 LOC.

### B.7 Selective depth-write (Batch 79) only fires on tiles, not standalone Models
`Cesium3DTile.js:1084` is the ONLY source setting `depthForTranslucentClassification`. Standalone Models with translucent material have `depthWrite: false`, so `pickPosition` over them returns the position behind the model. **Fix:** Allow `Model.classificationType !== undefined` OR explicit opt-in to set the flag. ~20 LOC.

### B.8 AGI_articulations + node-level transforms silently dropped
`WebGPUModelRenderer.js:1278` packs ONE `_computedModelMatrix` for every primitive of every node. `applyArticulations()` runs but `runtimeNode.computedTransform` is never read. Articulated rigs / non-skinned animated rigs break visibly. **Fix:** Pre-multiply per-primitive `nodeModelMatrix`. ~30 LOC.

### B.9 Classification & Advanced shaders missing `previousViewProjection` (DP-H41 violation)
GroundPrimitive, ShadowVolume, Vector3DTile*, GaussianSplat, PointCloud, PointCloudEDL, VoxelPrimitive — none have `previousMvpRelativeToEye`. TAA reprojection produces ghosting on these primitives. **Fix:** Add field per CameraUniforms invariant. ~10 LOC × 7 shaders.

### B.10 TAA motion-vector coverage limited to ModelRenderer
Collections (Billboard, Label, Polyline, PointPrimitive, Cloud), advanced (PointCloud, GaussianSplat, Voxel), classifiers (GroundPrimitive, Vector3DTile) — none emit `velocityCommand`. Animated billboards / polylines / particles ghost under TAA. **Fix:** MRT velocity per renderer OR per-renderer `motionVectorsValid` flag so TAA skips reprojection on those pixels. ~50 LOC × 5+ renderers.

### B.11 CSM cast list missing collections, classifiers, voxels, splats, BufferPrimitives
Only ModelRenderer + GlobeSurfaceRenderer set `_shadowCastLayout`. Tall billboards, polylines, Vector3DTile buildings — none cast shadows. **Fix:** Per-collection `_shadowCastLayout` opt-in. Significant; ~200+ LOC.

### B.12 Primitive lit shaders don't sample point-light cube depth
`pointLightCubeDepth` only in Globe + ModelPBRComplete. 22+ primitive shaders only consume directional `shadowDepthTex`. Point light near a primitive scene casts no shadow on primitives. **Fix:** Mirror globe/model cube-shadow code stack (~80 LOC × per shader). Could be inlined as a chunk.

### B.13 AmbientOcclusion algorithm switching has no runtime selector
SSAO + GTAO shaders both exist; `WebGPUAmbientOcclusionEffect` defaults to "hbao" with no `setAlgorithm()` mutator. Users can't reach GTAO without monkey-patching. **Fix:** Read `ao?.uniforms?.algorithm`; add `setAlgorithm()`. ~20 LOC.

### B.14 AutoExposure only registered in HDR mode; SDR scenes never adapt
`WebGPUSceneRendererEnsureResources.ts:333-342` gates `addAutoExposure` behind `if (hdr)`. SDR + day/night cycle goes fully black at night. **Fix:** Always-on autoexposure OR independent toggle. ~10 LOC.

### B.15 SSR uses 1×1 placeholder normal texture
`WebGPUSceneRendererEnvironmentalEffects.ts:107` passes `undefined /* normalTextureView */`. Reflections compute against zero normals; degenerate to vertical-only blur. **Fix:** Wire normal G-buffer OR compute normals from depth via `cross(dFdx, dFdy)`. ~30 LOC.

### B.16 TAA + HDR composition order: TAA runs after Tonemap (accumulates SDR)
`WebGPUPostProcessPipeline.ts:836-859` order: Tonemap → ColorGrading → TAA. With HDR, TAA history accumulates SDR — loses linear-domain precision. **Fix:** Reorder when `hdr === true`: AO → Bloom → DoF → AutoExposure → TAA → Tonemap → ColorGrading → FXAA. ~10 LOC + threshold re-tune.

### B.17 VolumetricFog HDR composite format mismatch
`WebGPUVolumetricFogRenderer.ts:813-836` builds composite pipeline once with first format passed. Doesn't rebuild when `outputFormat !== compositeBoundOutputFormat`. HDR + volumetric fog co-enabled → composite frame may be black. **Fix:** Pre-compile both `bgra8unorm` + `rgba16float` variants. ~40 LOC.

### B.18 `WebGPUComputeEngine` bypasses central `WebGPUComputePipelineCache`
`WebGPUComputeEngine.ts:263/295/337/379` calls `_device.createComputePipeline(...)` directly with own private `Map`. Two contexts (split-screen) re-compile same shader. **Fix:** Route through `context.webgpuComputePipelineCache.getOrCreateSync()`. ~20 LOC.

### B.19 `WasmArenaSlots` migration is 1/7 done
Only `WasmCullBridge` migrated. 6 other bridges still use slot-0 default. Concurrent bridge dispatch trampling each other's arena ptr. Blocks worker-pool work. **Fix:** Mechanical 6-bridge sweep. ~30 LOC × 6.

### B.20 Render bundle cache no invalidation on `_scenePipelineFormatGeneration` bump
HDR toggle bumps generation but never calls `bundleMgr.invalidate*()`. Cached bundles reference OLD format pipelines, fail validation when new pass encoder begins. **Fix:** Call `bundleMgr.invalidateByPrefix("env_")` etc. at format-bump sites. ~10 LOC.

## C. LATENT FINDINGS (top 12)

### C.1 `WebGPUDevicePool` fully orphaned — `acquireDevice()` never called
215 LOC with refcounted slots; zero callers. Multi-context split-screen each creates own device, doubling VRAM pressure. Doc lies about device sharing. **Fix:** Replace inline `requestAdapter()/requestDevice()` in `WebGPUContext._initialize` with pool. ~30 LOC.

### C.2 `gpuCullCommands()` exported but never called from live render path
`WebGPUSceneRenderer.ts:2056` defines the function with threshold gate; no caller invokes it. `WebGPUGPUCuller` allocated eagerly, burns ~256KB SOA buffers permanently. Mirrors HiZ + GPUSortKeys + PointCloudSort orphan dispatchers. **Fix:** Either consume from `executeFrustumLoop` OR delete `gpuCullCommands` and lazy-init the dispatcher.

### C.3 `WebGPURenderBundleManager` not registered with `_cacheRegistry` for device-loss
Plus `_storageBufferPool`, `_mipmapGenerator`, `_timestampProfiler`, `_indirectDrawManager` — none registered. Cached resources reference dead GPUDevice handles after recovery. **Fix:** Add `.register(...)` for each. ~10 LOC.

### C.4 R-7a CPU pass profiler telemetry collected but never read
~15 `performance.now()` calls/frame; data stored in rolling buffer; only readers are getter methods with zero invocations. **Fix:** Surface via CesiumDebug or pragma-strip in production. ~20 LOC.

### C.5 `WebGPUTimestampProfiler` has no consumers reading frame data
Same shape as C.4. `frameTimings` getter has no callers. **Fix:** Expose via `getDebugSnapshot()` or pragma-strip. ~15 LOC.

### C.6 `WebGPUVideoTextureManager` zero-copy `texture_external` path is dead
Never instantiated, never registered, never wired to Material. SCAFFOLDED tag in §B.2 hides the absence of consumers. **Fix:** Update tag to ORPHANED or wire through Material upload. ~5 LOC for tag fix.

### C.7 `WebGPUSync` (125 LOC) has no callers — orphan WebGL2 wrapper analog
`Sync.js` constructor throws on WebGPU; no `if (context.isWebGPU)` short-circuit. **Fix:** Either delete `WebGPUSync.ts` or add the dispatch in `Sync.js`.

### C.8 `WebGPUBindGroupCache` exposes no hit/miss statistics
Cannot tell from telemetry whether the dedup architecture is saving allocations. Future texture-view identity changes would silently drop hit rate. **Fix:** Add `_stats` matching `WebGPURenderPipelineCache` shape. ~15 LOC.

### C.9 Stale comments claim ComputePipelineCache "doesn't exist"
`WebGPUWeatherRenderer.ts:142-146` and `WebGPUVolumetricFogResources.ts:121-124` wording. Cache exists since Batch 76 and BOTH files actively use it 20 lines below. Misleading for archaeology. **Fix:** Edit comments. ~10 LOC.

### C.10 Variant smoke test only counts frames, no pixel verification
`Tools/variant-smoke-test.mjs:198-208` waits 5 RAFs and sets ready. Black canvas / silent fallback to WebGL passes the test. **Fix:** Sample `canvas.toDataURL()` and assert non-uniform pixels. ~30 LOC.

### C.11 `WebGPUSceneRenderer.ts` hardcoded viewport ignores `passState.viewport`
`setViewport(0, 0, this._width, this._height)` ignores `passState.viewport`. WebVR setter has no `isWebGPU` guard so stereo eye-split silently produces single-eye full-canvas. **Fix:** Add guard to throw on `useWebVR=true` for WebGPU; long-term route `passState.viewport`. ~10 LOC.

### C.12 `scene.sunBloom = true` allocates `SunPostProcess` even on WebGPU (unused)
`FramebufferOrchestrator.js:42-47` constructs `new SunPostProcess()` with no `isWebGPU` guard. WebGPU never invokes it. Resource leak per toggle. **Fix:** Add guard. ~5 LOC.
