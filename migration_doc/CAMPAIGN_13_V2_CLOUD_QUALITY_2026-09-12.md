## 1. Goals as measurable quality bars

### 1.1 The five view bands

Bands key on the CPU-f64 geodetic camera height the renderer already packs to slot 63 and the shader already reads (`ProceduralClouds.wgsl:2261`), not on `length(p) − R`, so a polar camera is not misbanded.

| Band | Camera height | What the user is doing |
|---|---|---|
| **Orbital** | ≥ 200 km | Whole or partial disc, limb visible, terminator in frame |
| **High-altitude** | 20–200 km | Continental view, deck subtends the frame |
| **In-atmosphere** | 2–20 km | Flight-sim regime — above, beside and between decks |
| **Ground** | 0–2 km, camera outside the deck | Looking up, at the horizon, and at shafts |
| **Inside-cloud** | camera between deck bottom and top | IFR entry / transit / exit |

### 1.2 The arithmetic that sets the orbital priority

| Quantity | Value | Basis |
|---|---|---|
| Screen pixel at a 2000-px full disc | **6.4 km** | 40,030 km circumference ÷ (π × 2000) |
| Current global weather texture | 256 × 128 = **156.4 km/texel** | `WebGPUProceduralCloudRenderer.ts:204-205` |
| Default EDR request | 96 × 48 = **417 km/texel** | `EdrWeatherSource.ts:46` |
| Shape-noise world period at `puffSize = 0.45` | **~7.4 km** | derived from `WebGPUCloudDensityDomain.ts:35,41` |
| Detail-noise world period | **~673 m** (~21 m voxel) | same |
| GFS 0.25° native | 1440 × 721 = **27.8 km/texel** | verified from a live `.idx` |

**Therefore:** from orbit the entire march integrates to a constant — the shape field's whole period is roughly one screen pixel and the detail field is two decades below it. What survives to the image is a **156 km/texel coverage field smeared across 24×24-pixel blocks**, lit at full noon on the night side (§0.5), with 85 % of every cloud pixel replaced by a flat camera-keyed haze tint (§0.4). No amount of march quality moves that. Orbital quality is a **field-plus-radiometry** problem, and the analytic shell is simultaneously the orbital quality answer, the orbital performance answer, and the first cloud feature `capture-and-diff.mjs` can score across backends.

This arithmetic also sets the ordering: the shell must not ship over a 156 km field. §5 puts the field-resolution rows **ahead of** the shell.

## 2. Tier ladder — two orthogonal axes, made effective by one resolver

**Both backends, under `R-2026-09-12-8`.** The S and L axes below are a **product surface**, not a WebGPU surface. `S_shell` and `S1`–`S3` × `L0`–`L3` resolve on **both** renderers after Wave 7; **`S4` (`ultra`) is WebGPU-only by design** (`C13-N12`), and the resolver must say so rather than silently clamping — `C13-N15d` is the row that documents the clamp and `C13-N41` is the row that exposes the axes publicly. The resolver itself (`C13-N10`) and the ladder (`C13-13`) are backend-neutral code and were always going to be; what changes under the ruling is that a WebGL consumer now exists to make the neutrality testable rather than notional.

### 2.1 Why the current ladder cannot be a product surface

1. **Two resolvers.** `resolveTier` picks the preset; `resolveCloudQuality` independently picks `(maxSteps, lightSteps)` from duplicated literals and duplicated altitude bands, and *its* output reaches the shader. The module docstring claims a single source of truth and the table docstring concedes it mirrors the legacy resolver — the file contradicts itself.
2. **Lighting is hostage to resolution.** Tier 3 is simultaneously the only `lightSampleScale 1.0` tier, the only straight-light-march tier, the only full-resolution tier, **and** the only tier without temporal reconstruction.
3. **Inert fields.** `powderStrength`, `isotropicFloor`, `ambientFloor` are declared and never read; the march hard-codes `powder = 0.5`; `curlAmplitude` is overridden by the config value; `lightSampleScale` has two sources of truth.
4. **One dead bit and one phantom value.** `CLOUD_QF_PROFILE_ON = 1 << 7` is declared in both halves and set/read by neither; `cloudVolumetricQuality: "ultra"` is documented at `CloudVolumetrics.js:164-171` and known to neither resolver.
5. **No public surface for either axis.** *[added 2026-09-12.]* `CloudVolumetrics.js:162` / `:171` are the only public quality dials. The S and L axes below exist entirely inside `WebGPUCloudTierPresets.ts`; no row in the draft added a public dial, a `CloudQualityTier` enum, JSDoc, a CHANGES entry or a Sandcastle control. The maintainer's "users can scale functionality down" is therefore designed and never exposed. **`C13-N41` is the row that exposes it.**

### 4.3 How the shell and the volume share one field — the invariant

**Both render the identical `weatherTex`.** After `C13-N22` and `C13-N23` that is concretely:

- **one texture**, `1440 × 721 × 3` rgba8 (~12.5 MB), slices = {low, mid, high} decks;
- **one UV function** — `worldToWeatherUV` (`ProceduralClouds.wgsl:528-543`) with its CPU twin `WeatherMapSeam.weatherUVFromLonLat` (`Scene/Weather/WeatherMapSeam.ts:62-69`), pinned together by `Tools/visual-regression/weather-map-seam.spec.mjs` — **whose `TEX_W`/`TEX_H` mirror at `:67-68` moves in the same batch** (§0.14);
- **one seam policy** — `addressModeU: "repeat"` (producers exactly periodic in longitude) and `applyEquirectPolarLowPass` (`WeatherMapSeam.ts:9-26`, `:212-265`), an exact identity below ~59°;
- **one no-data policy** — default fill `"procedural"`, byte-continuous with the no-provider render, because "an absence of data is not an observation of a clear sky" (`WeatherFieldGrid.ts:45-72`) — **and `C13-N44` is what makes that true under failure, not just under absence**;
- **one bounds convention** — `weatherTexBounds` stays the full globe (`:3670-3675`); a regional field is placed by the **packer**, which is the resolution `C13-08` reached over pointing the bounds at the region;
- **four channels, all live** — R coverage, G genus bias, B **base shift (`baseMeters`, produced and consumed today — §0.13)**, A density bias (`ProceduralClouds.wgsl:1226-1249`). **G is NOT free**: it has two producers and a live consumer, so `C13-N27`'s regime id needs its own channel or a documented bit-split (§3 WS-F).

Then the shell↔march handover (`C13-N16`) is a **blend of two renderings of one field**, not a content change. This is the only architecture in which the orbital and in-atmosphere goals do not fight each other, and it is the design SpaceEngine's author named and never finished and that NOAA/CIRA's GeoColor validates operationally.

**Determinism contract**, binding on every weather row: fields depend on geographic identity, physical time, model revision and an explicit seed — **not** camera position, frame rate or mutable global randomness. Advection happens in the shared tangent frame; RTE high/low splitting applies only in rendering, so camera precision never moves the weather.
**Honesty contract:** synthetic output is never presented as observation; provenance must reach the sampler, legend and exports; a synthetic-as-observed mutant must fail. **`C13-N45` is the row that implements it** — the draft quoted it as binding and filed nothing.

A twin that drifts is worse than no twin: it produces a WebGL image that *looks* supported and is silently a different renderer.
    **The proposed guard is `C13-N54`, three layers, each with its own inertness mutant** — and it is deliberately modelled on what the fork already does rather than on anything new (§0.19):
    **(1) Provenance, machine-checked.** Every ported GLSL function carries a comment naming its WGSL source and line span, in the shape `GlobeTerrain.wgsl` already uses for `VectorCommon.glsl` (`:4214` "Line-for-line port of `VectorCommon.glsl::vectorOffsetToLine`", and `:4144`, `:4207`, `:4238`, `:4249`, `:4276`, `:4317`). A Node spec asserts every such reference resolves to a real symbol in a real file. This catches *deletion* and *rename*, not semantic drift.
    **(2) A CPU reference model both sides must match.** Extend `cloud-march-transfer.spec.mjs` — which already models the march's transfer function — so the **model**, not the text, is the contract. This is the layer that catches semantic drift, and it is the layer the `csm_eyeToCartographicDelta` precedent does **not** have (it relies on byte-identity, which is available for a 40-line function and not for a 3,157-line shader).
    **(3) A structural fold.** A generated manifest of `(function name → normalised body hash)` for both files; editing one side without the other fails a Node spec **by name**. Structural rather than per-site, in the spirit of the pipeline-key module fold — "a new define bit cannot alias in the pipeline cache regardless of whether anyone remembers step 5" — because a guard that depends on remembering is not a guard.
