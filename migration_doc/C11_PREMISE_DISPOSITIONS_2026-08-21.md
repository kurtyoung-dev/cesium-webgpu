## C11-109 — quantized shadow layout

### Queue claims

The full queue cell says premise-reconcile and “likely doc-close” (`migration_doc/QUEUE_2026-07-18_CAMPAIGN11.md:625`; W1 at `:1585-1588`). The expanded cell claims quantized terrain uses missing stride-8 u16 and stride-12 f16 layouts and therefore cannot cast shadows on WebGPU (`migration_doc/campaign11_planning/CANDIDATE_REGISTER.md:237`). The guide further claims BITS12 arrives uniformly as `float32x4`, stride 16, that `quantized12` covers it, and that the adapter exposes the real stride (`migration_doc/campaign11_planning/guides/G8-defaults-parity-env.md:93-169`).

### Current HEAD evidence

1. **The named u16/f16 formats are stale.** `TerrainEncoding` selects `TerrainQuantization.BITS12` by extent at `packages/engine/Source/Core/TerrainEncoding.js:53-78`, but its attributes use `ComponentDatatype.FLOAT` at `:638-645` and `compressed0` is three or four float components at `:675-690`.
2. **BITS12 is not uniformly stride 16.** Its base is three floats, with one float each for optional Web-Mercator T and vertex normal and three more for an optional geodetic normal at `packages/engine/Source/Core/TerrainEncoding.js:607-629`. The color pipeline independently derives `float32x3`/12-byte or `float32x4`/16-byte bases, 20 bytes when both single-float options are present, and an additional 12-byte geodetic tail at `packages/engine/Source/Renderer/WebGPU/WebGPUGlobeSurfacePipelines.ts:178-230`. Valid BITS12 strides are therefore 12, 16, or 20 bytes, optionally becoming 24, 28, or 32.
3. **A quantized shadow variant exists, but it is only the 16-byte shape.** `SHADOW_CAST_VARIANTS.quantized12` decodes the packed 12-bit position pairs and applies scale/bias/RTE at `packages/engine/Source/Renderer/WebGPU/WebGPUShadowMapRenderer.js:471-544`; its vertex buffer is fixed to `float32x4`, stride 16 at `:545-550`.
4. **The producer retains the true stride, but the scene adapter discards it.** `WebGPUGlobeSurfaceRenderer` carries `gpuResources.strideBytes` in the command descriptor at `packages/engine/Source/Renderer/WebGPU/WebGPUGlobeSurfaceRenderer.ts:1943-1954`. The adapter routes every quantized command to `quantized12` and forcibly publishes `vertexStride: 16` at `packages/engine/Source/Scene/GlobeSurfaceTileProviderRendering.js:1360-1387`.
5. **That forced value controls the cast pipeline.** Explicit `_shadowCastLayout` wins at `packages/engine/Source/Renderer/WebGPU/WebGPUShadowMapRenderer.js:679-683`. `_getOrCreateCastPipeline` keys and applies the caller's override stride at `:814-869`, and the draw loop passes the command's reported stride at `:1639-1684`. Thus the non-16 layouts would walk the real vertex buffer with a 16-byte cast stride; the 12-byte/no-option case also needs a `float32x3` declaration rather than the current `float32x4` declaration.
6. **The guide's speculative u16/f16 model residual has no current producer in the native WebGPU model path.** Model POSITION/NORMAL/TEXCOORD data is converted or dequantized into `Float32Array` storage at `packages/engine/Source/Scene/Model/ModelPrimitiveGeometry.js:485-494,630-648,975-1046`, including `KHR_mesh_quantization`. The renderer then assigns explicit `modelP12`/skinned/instanced cast layouts rather than stride-inferencing raw quantized accessors at `packages/engine/Source/Renderer/WebGPU/WebGPUModelRenderer.ts:7338-7411`. The directly proven residual is terrain adapter routing, not the guide's hypothetical stride-8/stride-12 model format.

### History and disposition

`git log -S "_shadowCastLayout: cmdDesc.isQuantized"` identifies `4e91c1238a9b4299199f7834bc226ad60e57e74d`, which added the partial variant and the force-16 adapter route. It discharged “no quantized variant exists,” but not full producer-layout coverage.

**Disposition: RE-SCOPED.** Corrected premise: BITS12 terrain uses packed float32 attributes, not the register's u16/f16 formats. Quantized shadow casting exists and is structurally aligned only for the 16-byte subset; the adapter mis-describes valid 12/20-byte layouts and their optional geodetic tails.

Minimal remaining work: preserve `cmdDesc.strideBytes` for quantized commands, select an x3-compatible cast vertex layout for the three-float base and the existing x4 layout for the other bases, and let the current stride-keyed pipeline path carry the actual larger stride. No engine change was made.
