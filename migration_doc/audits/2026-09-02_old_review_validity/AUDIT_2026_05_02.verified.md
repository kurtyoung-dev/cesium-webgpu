### 1.1 B.11 — corrected text

The gap itself is confirmed at today's tree: WebGPU cascaded shadow maps take casters only from renderers that set `_shadowCastLayout` — models (`WebGPUModelRenderer.ts:7726`), globe tiles (`WebGPUGlobeSurfaceTileBuffers.ts:541-557`, fed by `GlobeSurfaceTileProviderRendering.js:1506`) and geometry primitives (`WebGPUPrimitiveShadowCast.ts:248`). `WebGPUVoxelRenderer.ts` and `WebGPUGaussianSplatRenderer.ts` set it nowhere; both only *receive* (`shadowMatrix` / `shadowDarkness` uniforms at `WebGPUVoxelRenderer.ts:375-378` and `WebGPUGaussianSplatRenderer.ts:592-595`). Upstream WebGL does not cast from them either, and screen-space collections (billboard, label, point, polyline) are deliberate non-goals on both backends. Casting from volumetric content needs a deep-shadow-map or transmittance-accumulation technique rather than a cast-layout registration, so it stays demand-gated.

**Correction to the judgement's scope:** the migrate text asserts the id `NEW-CSM-VOLUMETRIC-CASTERS` "is only referenced" and "must be given a defining row". That overstates it. The id has two records that carry a disposition, not bare mentions:

That register declares itself the canonical consolidation and the superseder of `AUDIT_2026_05_02.md` (`ISSUES_AND_FIXED_BUGS.md:2`), so the id is owned there.
- `NEXT_QUEUE_2026-07-04.md:101` — the demand gate ("demand", same rationale).

What is genuinely absent is a `DEFERRED_WORK.md` ledger entry (grep: zero hits in that file) and any C18 row — `QUEUE_2026-08-09_CAMPAIGN18.md` has no voxel/splat shadow-casting row (its only "shadow" hit, :93, is a cloud-shadow probe name).
