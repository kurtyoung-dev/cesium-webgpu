### M-R5 — the `debugShowBoundingVolume` half is still open for the four named collections

The judgement marks M-R5 **RESOLVED**, with migrate text "Definition only: resolved to WebGL
parity", on the strength of "`debugShowBoundingVolume` plumbs through collections into
`WebGPUBoundingVolumeDebugPass.ts`". That is true of the `Buffer*` / `GeoJsonPrimitive`
family only. For the four collections M-R5's own title names, the flag is dropped:

- **WebGL sets it on the command.** `Scene/BillboardCollection.js:1220`
  (`command.debugShowBoundingVolume = this.debugShowBoundingVolume`),
  `Scene/PointPrimitiveCollection.js:842`, `Scene/PolylineCollection.js:802` and `:898`.
- **The WebGPU renderers never do.** `grep -c debugShowBoundingVolume` returns **0** for
  `WebGPUBillboardRenderer.js`, `WebGPULabelRenderer.js`, `WebGPUPointPrimitiveRenderer.js`
  and `WebGPUPolylineRenderer.js`. Their commands carry `owner` and `boundingVolume` (e.g.
  `WebGPUBillboardRenderer.js:1355-1356`), so culling works, but not the debug flag.
- **The consumer filters on exactly that flag.** `WebGPUSceneRenderer.ts:3652` skips any
  command with `cmd.debugShowBoundingVolume !== true`, so the pass never sees these
  collections.
- **The WebGL assignment is unreachable on WebGPU.** `BillboardCollection.js:750` takes the
  feature-renderer early return well before the command-build block at `:1195-1228`.
- **No row owns it.** `DEFERRED_WORK.md:5012`
  (`NEW-BUFFERPRIMITIVE-BOUNDING-VOLUME` → `NEW-GEOJSON-WEBGPU-BV-DEBUG-DRAW-PASS`) is scoped
  to the three `Buffer*` renderers and `GeoJsonPrimitive`; `NEXT_QUEUE_CAMPAIGN5.md:17` is the
  same lane. Nothing covers Billboard / Label / Point / Polyline.

Net effect: setting `billboardCollection.debugShowBoundingVolume = true` (or the label, point
or polyline equivalent) draws the red wireframe on WebGL and nothing on WebGPU. Severity is
debug-tooling parity, not rendering correctness — but the item must migrate as **PARTIAL**
with this text, not as "resolved to WebGL parity", and it needs a row.

The rest of M-R5 is upheld: `pickOnly` **is** set by the billboard, point and polyline WebGPU
renderers (one site each; `WebGPULabelRenderer.js` has none, consistent with labels picking
through their glyph billboard collection) and is consumed at
`WebGPUSceneRendererPickPass.ts:974-980`; and the judgement's "collections still do not set
`castShadows` / `receiveShadows`, which matches upstream WebGL" is **correct** — no
`castShadows`, `receiveShadows` or `executeInClosestFrustum` assignment appears on any command
in `BillboardCollection.js`, `PolylineCollection.js`, `PointPrimitiveCollection.js` or
`LabelCollection.js`.
